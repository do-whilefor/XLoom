# 原件精读、重复读取与 Chat／Run 验证

2026-09-14，本批延续 [Wiki 结构接入](wiki-structure-validation.md)，优化现有
原生 read、Wiki 来源包和应用生命周期。没有新增 Agent、外挂 Skill 或另一套存储。

## 本批改动

- 证据元数据提供 `originalReadPath`，明确 `bodyIncluded=false`。模型可以从完整
  来源包直接进入归档原件，无须再次打开 Wiki 页面寻找路径。
- 原件默认分页最多 4,096 字节，适配短文件及 UTF-8 字符边界；显式范围仍严格
  校验。`nextReadPath`／`startReadPath` 支持继续和回读；每次读取都核验完整原件，
  重复读取也不跳过哈希、大小或文件状态检查。
- 同一个 read 实例记录交付过的公开记录版本和原件字节范围，跨入口提示资料
  重叠、未读原件和重复范围。正文继续返回，不持久化阅读记录、不跨角色共享，
  不把“交付过”当成“理解了”或“复核通过”。提示不会挤掉字符预算内的来源正文。
- 问题检索遇到缺失来源依赖时不再误报完整；最低 128 字符预算下的溢出诊断
  保持在预算内。原件阅读与重复交付协议见 [任务内 RAG](retrieval.md)。
- 修复关闭空闲应用覆盖 Run 暂停／错误原因的问题。关闭、重开保留原状态与
  诊断；关闭活动任务仍取消运行并释放工作区锁。
- 在 Execute checkpoint 协议中明确 Evidence 仅允许 `ref/path/description`，
  降低模型添加未支持字段的概率；严格解析和拒绝无效提交的规则保持生效。
- 消除 Wiki 上下文中“读完来源包仍需读取索引看警告”的矛盾引导，明确完整
  原生来源包已携带当前警告。元数据维护只需提交 Wiki 修订，读件／审计日志
  不应为了证明维护行为而另行登记为新观察。
- 首次观察没有已登记 Fact 时，明确省略 `combination`，把未验证条件保留在
  步骤描述中。为空的 `combination.requires` 仍被拒绝；修复提示给出合法表达，
  不自动删除条件或伪造 Fact ID，也不增加协议修复次数。

## 可重复的真实模型验证

```powershell
node --import tsx scripts/validate-chat-run-reading.ts --live --output .xloom/checks/chat-run-reading/report.json
```

脚本先从当前项目配置解析 Chat／Decide／Execute 模型，再隔离临时工作区和
`XLOOM_HOME`。使用真实 `AppController`、`ChatSession`、`PiRunner`、文件工具、
原生 read 和 SQLite；仅包装已有模型解析结果以统计请求与检测 Chat 内容泄漏，
不伪造模型输出。模型使用当前配置的 `opencode-go/deepseek-flash`。

本次回放不设金额、token 或模型请求轮数上限；单角色 240 秒、阶段 900 秒和
任务 20 分钟用于发现卡住的测试。报告与合成工作区保留在本地，失败不覆盖，
不写入真实项目的研究任务。报告中的 cost 不是供应商账单。

验证覆盖：Chat 写／改／读／PowerShell、关闭后恢复聊天、拒绝并发、取消及恢复、
重置与旧存档保留；Run 文件读回对照、证据归档、合成假设复核关闭、新鲜元认知、
原生原件读取、Wiki 元数据维护；最后检查暂停任务重开、Chat／Run 状态隔离和
已完成任务不重复调用模型。Chat 私有标记不能进入任一 Run 模型上下文或黑板。

精读阶段实际有 9 次 `original_read`：Decide、Execute、metacog 各读取三份
72／84／96 字节的原件。每个角色的 `fullyDeliveredOriginals` 独立从 1 增至 3，
没有跨角色使用阅读记录。没有额外打开 Wiki 的 index.md 或 pages 文件，也没有
把核对／审计日志另行登记为 Evidence。Chat 私有标记没有进入 Run 上下文或黑板。

仍存在两次原生入口重叠：Decide 在完整搜索后再读 record，反馈重复 12 条记录；
Execute 从 wiki 搜索切到 combined，反馈重复 13 条记录，两次 `newRecords` 都为 0。
这验证了跨入口重复识别确实工作，也说明提示没有彻底消除模型的重读选择。
本批不隐藏正文或强制禁止重读；不能把“没有重复打开 Wiki 文件”扩展为“没有任何
重复读取”。长原件的 UTF-8 连续分页由离线测试覆盖，本次模型场景使用短原件。

真实回放明确给出操作要求，是应用引擎与接口协议集成验证。它不能证明 GUI
键盘／渲染无 bug、无引导原件理解准确率、真实漏洞召回率或所有配置模型均正常。
本批没有建立 token 降低或大规模性能的对照结论。

## 离线验证

`npm run check` 通过：54 个测试文件、1,484 项测试，包含类型检查和构建。
独立回放脚本与新增阅读测试也通过 NodeNext 严格 TypeScript 检查。

新增阅读测试覆盖短原件直达、混合 UTF-8 连续分页并重建全部字节、严格范围拒绝、
跨入口记录重叠、角色隔离、片段／不完整包不算精读、重复读重新验真、哈希版本
变化后的覆盖重置、预算和实际工具反馈、CLI 默认读取及缺失来源。应用测试覆盖
空闲错误／暂停的关闭重开和活动 Run 关闭取消；协议测试保留紧凑性约束并核对
checkpoint 的有效字段与拒绝后修正规则。
新增协议回归还验证空组合不会被自动丢弃，以及 PiRunner 的一次无工具修复能
保留未验证条件并返回无虚构 Fact ID 的首步计划。
