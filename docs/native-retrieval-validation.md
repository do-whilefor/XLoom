# 原生检索入口验证记录

2026-09-14，本轮将 Wiki／原件显式搜索、指定消费者的能力发现接入现有 read，
并用已配置的 `opencode-go/deepseek-flash` 验证真实工具调用和后续规划。

## 可重复运行

在源码工作区运行（显式 --live 会调用配置模型并产生模型用量）：

```powershell
node --import tsx scripts/validate-native-retrieval.ts --live --output .xloom/checks/native-retrieval/report.json
```

脚本从当前工作区配置解析 Decide 模型，然后在临时工作区及隔离 XLOOM_HOME
中建立合成任务。它保留原始配置和真实研究任务，只向模型提供合成黑板、Wiki 与
样本文件。每阶段使用 fresh Pi Agent、原生 read、真实 SQLite 提交。第一阶段后
不执行模型建议的目标动作，由测试装置提交新的合成授权观察，再开始第二阶段。
临时资料与逐轮运行记录保留，报告记录路径、用量、检查项和最终规划。

这个回放明确要求模型使用 Wiki 搜索与能力发现，检查的是接口可用性和规划协议；
不等同于无引导自主研究。完整 Decide → Execute → Decide、原件文件工具、缺口
复核及后续选步还由 tests/loop-integration.test.ts 的离线供应商回放验证。

## 三次回放及修正

| 回放 | 结果 | 发现和处理 |
| --- | --- | --- |
| 第一次，7 次请求 | 断言失败 | 模型读到兼容授权及旧消费者的 source_changed，正确保留 plan=null；验证器错误地要求有授权就应产生计划。修正预期，分别检查提供者兼容性与消费者来源复核，不修改运行时的待复核规则。 |
| 第二次，9 次请求 | 规划协议失败 | 模型将 revisit 放到新建子目标。原校验拒绝，且回放总 token 预算耗尽，未进入修复调用。缺口提示补充沿用原 goalId 的要求，错误明确返回预期／实际目标，修复指导要求保留 revisits；回放专用总预算提高以留出纠正余量。 |
| 第三次，7 次请求 | 两阶段通过 | 模型调用 Wiki／组合搜索、指定消费者发现、问题与原件精读，保留来源更正，创建合法 revisit；没有提前解决缺口或结束根目标，工具错误为 0。 |

前两次失败记录保留在本地 `.xloom/checks/native-retrieval-20260914/report.json`
和 `report-2.json`，最终记录是 `report-3.json`。这些文件不随安装包发布。

第三次的具体用量（包含 Xloom 累计的缓存输入）如下：

| 阶段 | 请求数 | 输入 tokens | 输出 tokens | 预期行为 |
| --- | --- | --- | --- | --- |
| 授权缺失 | 4 | 61,921 | 5,086 | 读取判断及来源，识别无提供者，保持目标未完成 |
| 新授权到来 | 3 | 73,869 | 8,021 | 读取更正和原件，保留消费者待复核，按原 goalId 规划 revisit |
| 合计 | 7 | 135,790 | 13,107 | 两个 fresh 规划阶段通过全部适用检查 |

报告中的 cost=0 不作为免费调用或实际价格的证明。此次没有建立成本／token 降低
的对照基线，仍可观察到多种入口对同一来源的重复读取。需要后续真实任务样本
评估召回率、重复读取和上下文成本；不能由本次合成回放推断漏洞发现率或性能提升。
