# 来源交付与邻近上下文验证

2026-09-15，本批修复针对 checkpoint JSON 数组提前闭合和超预算来源包反复返回空结果。
日志显示四次读取请求指向不同 Evidence ID，因此相似终端提示并非同一事件被重复渲染。
结构化 checkpoint 由运行时序列化，再通过原有严格校验和事务；无效字符串不猜测修补。

在真实故障任务的 SQLite 上以只读连接构建内存检索结果，不实例化 Store、不写任务：
前三个入口各展开 43 条记录，第四个展开 47 条。旧预算均无法交付；新分页分别以两页
完成。紧凑 JSON 页大小分别为 61,229 + 8,230 和 62,660 + 13,023 字符。
这是确定性来源交付回放，不是模型实际完成任务或复核全部来源的证明。
回归测试只复现关系规模和错误数组形状，没有复制真实来源正文。

随后增加原文命中的 `contextReadPath`：默认向前、向后各展开最多 1,024 字节。
`tests/wiki-originals.test.ts` 使用合成长原文，将身份／版本前提放在原命中前，
否定观察放在命中后；两者均不在原片段内，扩展读取均能交付。远处条件仍标为省略。
测试还覆盖中文／emoji、流式边界、文件首尾、无效焦点、超限、篡改、归档越界、
原生和 CLI 入口一致性，以及按实际扩展字节统计的本轮读取覆盖。

固定的 20 条合成检索查询保持不变，比较结果如下。两组仅为不同主题的测试划分，
不能解释为真实任务准确率；本批没有修改检索排名。

| 测试划分 | Recall@5 前／后 | 检索包字符数前／后 |
| --- | --- | --- |
| development（10 条） | 1.0 / 1.0 | 70,191 / 73,238 |
| acceptance（10 条） | 1.0 / 1.0 | 71,895 / 74,995 |

来源／条件保留、无匹配查询、精确字节定位均通过，黑板未改变。附加导航与说明使这些
检索包合计增加约 4.3% 字符，尚未计入选择扩展读取后的正文。没有测得模型准确率提升，
也没有把更大窗口描述为更省 token；其直接收益是提供可校验的邻近条件读取路径。

分页仍需多次读取，并保留可能相关的全部依赖，不能解决来源图本身过度关联的问题。
邻近展开仍可能遗漏远处条件；完整原件校验成本仍在。当前没有为此引入向量服务，
后续应以真实任务中的语义漏检与总交付成本决定是否需要新的检索方案。
