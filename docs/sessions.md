# 会话与任务

研究资料属于 task，一次 task 内有多次 Decide / Execute / 元认知调用。`/run 目标`
创建独立 task；`/start` 继续已选任务，`/hint` 补充当前研究信息。

- `/tasks` 列出当前工作区的任务；`*` 标记当前选择。
- `/open 完整任务ID` 选择历史任务并读取黑板，不调用模型；随后 `/start` 继续。
- `/open @legacy` 选择迁移保留的旧式项目根黑板（存在时）。
- `/paths` 显示用户数据、项目、配置、聊天和当前任务目录。
- 非交互终端使用 `xloom tasks`、`xloom paths`，这两个入口不恢复执行或修改任务。

数据位于 `XLOOM_HOME` 或系统用户目录的 `.xloom/projects/<工作区哈希>/`。
移动工作区会改变身份；切换终端工作目录不会自动切换到源码安装目录。
`current-task.json` 保存选择；各 task 的 SQLite、证据、Wiki 和 runs 长期保留。
切换任务要求当前调用结束；损坏的任务列为不可读取，不自动删除。

打开旧任务会按现有恢复流程检查中断状态并重建 Wiki/RAG 投影；正式研究状态以
SQLite 为准。恢复后从黑板重新规划，不重放结果不确定的工具调用。

## 普通聊天

应用将普通聊天保存到项目数据目录 `chats/chat-<UUID>/continuation.json`，
`chats/current.json` 保存当前选择。每个完整消息边界原子保存上下文、用量和待完成
工具 ID；写入失败时停止后续模型调用，并阻止尚未执行的工具。

重启后的第一次普通输入会恢复同工作区、同模型配置和同解析端点的上下文。模型或
端点改变时新建聊天，不向新端点发送旧历史。`/history` 可以离线查看当前保存的
用户/助手文本及文件路径；工具记录仍保存在文件中。`/new` 新建聊天并保留旧文件，
不清理研究任务。关闭应用只释放内存，不改变当前聊天指针。

若退出时工具结果尚未确认、文件损坏或身份不符，拒绝自动恢复；保留原件，先检查
可能的工具副作用，再用 `/new` 开始新的聊天。目前没有旧聊天选择器或逐事件 UI
回放；历史上下文可能经过压缩。恢复用量在首次继续后显示，不代表重新消耗模型额度。

检查点过滤助手思考及不透明供应商签名，并对运行时已知模型凭据脱敏；这不是任意
业务秘密的通用识别器。聊天内容不进入研究黑板、Wiki、RAG 或其他 Agent 的上下文。
