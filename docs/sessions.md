# 会话与任务

每次启动都是新的会话：聊天上下文、用量和当前任务选择从空状态开始，不自动载入
旧聊天、压缩摘要、工具结果或任务黑板。历史文件保留为归档，不进入新会话。

研究资料属于 task，一次 task 内有多次 Decide / Execute / 元认知调用。`/run 目标`
创建独立 task；`/start` 继续本次会话已选任务。尚未选择任务时，若配置有显式目标，
`/start` 为该目标创建新 task，否则提示使用 `/run`。`/hint` 补充当前研究信息。

- `/tasks` 列出当前工作区的任务；`*` 标记本次会话的选择，刚启动时没有选中任务。
- `/open 完整任务ID` 选择历史任务并读取黑板，不调用模型；随后 `/start` 继续。
- `/open @legacy` 选择迁移保留的旧式项目根黑板（存在时）。
- `/paths` 显示用户数据、项目、配置、聊天和当前任务目录。
- 非交互终端使用 `xloom tasks`、`xloom paths`，这两个入口不恢复执行或修改任务。
- `xloom run --headless` 每次为配置中的显式目标新建 task，不恢复上次任务。

数据位于 `XLOOM_HOME` 或系统用户目录的 `.xloom/projects/<工作区哈希>/`。
移动工作区会改变身份；切换终端工作目录不会自动切换到源码安装目录。
`current-task.json` 保存最近选择，供离线 `status` / `report` / `tasks` / `paths` 使用；
启动会话不读取它。各 task 的 SQLite、证据、Wiki 和 runs 长期保留。
切换任务要求当前调用结束；损坏的任务列为不可读取，不自动删除。

打开旧任务会按现有恢复流程检查中断状态并重建 Wiki/RAG 投影；正式研究状态以
SQLite 为准。恢复后从黑板重新规划，不重放结果不确定的工具调用。

## 普通聊天

应用将普通聊天保存到项目数据目录 `chats/chat-<UUID>/continuation.json`，
`chats/current.json` 仅记录最近发布的聊天 ID，不用于恢复会话。每个完整消息边界原子保存上下文、用量和待完成
工具 ID；写入失败时停止后续模型调用，并阻止尚未执行的工具。

同次会话中的连续输入保留上下文；新实例首次聊天使用新的 UUID 和独立归档文件，
即使工作区、模型与端点相同也不恢复旧消息或用量。模型或端点改变时同样新建聊天。
`/history` 只查看本次聊天的用户/助手文本及文件路径，刚启动时为空；工具记录仍
保存在文件中。`/new` 新建聊天并保留旧文件，不清理研究任务。关闭应用释放内存和
聊天选择；磁盘归档指针不会让下一次启动重新关联旧文件。

Chat 和 Run Execute 都使用 `read / write / edit / powershell / chrome`；Decide／元认知仅用
`read`。Chrome 连接按工作区与 `XLOOM_HOME` 常驻，聊天重置、模式切换及应用退出不主动断开，
可用 `/chrome disconnect` 手动断开，`/chrome connect` 允许重连。连接复用不会共享聊天历史；
Chat 的浏览器原件存入 `chats/artifacts/<聊天ID>/`，不自动成为研究证据。详见 [Chrome](chrome.md)。

旧聊天存在未确认工具、损坏文件或不匹配身份时，也不会被新会话读取或阻止新聊天。
归档原件保留，工具已产生的文件等副作用仍存在；重新执行相关操作前应检查结果。
目前没有旧聊天选择器或逐事件 UI 回放；同次聊天的上下文可能经过压缩。

检查点过滤助手思考及不透明供应商签名，并对运行时已知模型凭据脱敏；这不是任意
业务秘密的通用识别器。聊天内容不进入研究黑板、Wiki、RAG 或其他 Agent 的上下文。
